# Попробовать модульный режим

[Русский](../ru/modular.md) | [English](../en/modular.md) | [简体中文](../zh-CN/modular.md)

Это локальный инструмент для подготовки установки. Он не подключается к VPS
и не меняет работающий VPN. Удалённое применение и управление каскадом из Telegram
будут следующим этапом.

## Собрать инструмент

Нужен Go 1.26.9. Из корня репозитория:

```bash
mkdir -p bin workbench
go build -o bin/lego-vpnctl ./cmd/lego-vpnctl
cp examples/cascade.json workbench/installation.json
bin/lego-vpnctl topology plan workbench/installation.json
```

В примере один вход и три выхода. Адреса учебные, для настоящих серверов они
не подходят. Есть и другие примеры: `direct.json`, `separate-control.json`,
`xhttp-tls.json` в папке `examples`.

## Описать серверы

- `control` управляет установкой, но сам по себе не передаёт трафик.
- `entry` принимает подключения пользователей.
- `exit` выпускает трафик каскада в интернет.

Роли можно совмещать. В установке ровно один контрол. Число входов и выходов
не ограничено фиксированным значением. Страна служит подписью, а не ограничением.

Маршрут содержит `entry_id` и необязательный `exit_id`. Без выхода это прямое
подключение. С выходом это каскад из двух узлов. Более длинных цепочек нет.

Несколько маршрутов могут использовать один вход и порт, если совпадают профиль
и домен. Разные ключи выбирают нужный выход. Если выход недоступен, маршрут не
переключается напрямую. Для межсерверных связей по умолчанию используется
REALITY на TCP 10443. Порт меняется через `relay_port` у выходной ноды.

Можно задать `reality_target` в формате `host:port` и `reality_server_name`.
Они задаются вместе. Без них используется `www.microsoft.com:443`.
Его пригодность для своей сети надо проверить отдельно.

Поле `owner` сейчас должно быть `lego`. Имена `remnawave` и `marzban` зарезервированы
для адаптеров. Планировщик откажется готовить такую ноду, пока адаптер не установлен.
Он не будет молча забирать управление у панели.

## Создать ключи и доступ

```bash
bin/lego-vpnctl topology init workbench/installation.json workbench/state.json
bin/lego-vpnctl topology grant workbench/installation.json workbench/state.json phone "Мой телефон" uk us ca
bin/lego-vpnctl topology render workbench/installation.json workbench/state.json workbench/generation-1
```

Получатся конфиги в `generation-1/nodes`, подписки в `generation-1/subscriptions`
и список хешей в `manifest.json`. Вывод команды не содержит ключей или ссылок.
Подписка содержит отдельный ключ для каждой разрешённой локации.

`state.json` содержит приватные ключи. Инструмент создаёт его с правами 0600,
а каталог генерации с правами 0700. Это подготовка файлов, не production-хранилище
контрола: файл пока не зашифрован. Не публикуйте `workbench`, не отправляйте его
в чат и не открывайте целиком веб-сервером.

Имена файлов подписок случайные и сохраняются между генерациями. Можно публиковать
только каталог `subscriptions` через отдельно настроенный HTTPS-сервис, без листинга
и кэша. Генератор не поднимает этот сервис. Публикация каталога `nodes` раскроет ключи.

## Изменить установку

После добавления серверов или маршрутов:

```bash
bin/lego-vpnctl topology extend workbench/installation.json workbench/state.json
bin/lego-vpnctl topology render workbench/installation.json workbench/state.json workbench/generation-2
```

`extend` сохраняет старые ключи. Новая локация не выдаётся существующим устройствам
сама по себе. Чтобы изменить список локаций телефона с сохранением прежних ключей
на оставшихся маршрутах и ссылки подписки:

```bash
bin/lego-vpnctl topology routes workbench/installation.json workbench/state.json phone uk us ca
```

Удалённые из списка маршруты больше не выдаются этому устройству.
Повторный `init` для существующего файла запрещён, чтобы случайно не сбросить доступы.
Каждая генерация создаётся в новом каталоге.

## Отозвать или вернуть доступ

```bash
bin/lego-vpnctl topology device workbench/state.json phone disable
bin/lego-vpnctl topology render workbench/installation.json workbench/state.json workbench/generation-3
```

Из новой генерации исчезнут и подписка, и ключи на входе. Пока новая конфигурация
не применена на сервере, старые импортированные ключи продолжают работать.
Чтобы вернуть прежние ключи и ссылку, используйте `enable` и новую генерацию.

Удаление маршрута из описания убирает его из нового экспорта и конфигов.
Старые ключи остаются в приватном состоянии для осознанного отката.

## Профили и домены

```bash
bin/lego-vpnctl profiles list
bin/lego-vpnctl topology dns workbench/installation.json
```

REALITY Vision реализован; XHTTP REALITY и XHTTP TLS пока экспериментальные.
Для TLS нужен свой домен и отдельно подготовленный сертификат.
Подробнее в [инструкции про домены](domains.md).

Для управляющего API доступны `GET /v1/profiles` и `POST /v1/topology/plan`.
План не содержит секретов и ничего не применяет. В Telegram каталог доступен
через `/profiles` после привязки владельца.

## Что проверено

Автотесты проверяют сохранение ключей, отзыв доступа, конфликты портов,
размещение контрола и подготовку плана на 1003 узла. Последнее проверяет модель,
а не вместимость настоящего сервиса.

При заданном `XRAY_BINARY` тест поднимает настоящие процессы Xray на loopback
и проверяет прямой выход и каскад. У них разные исходящие адреса, поэтому
случайный прямой выход вместо каскада не пройдёт проверку.

Проверки операторов РФ и Китая, совместимости версий мобильных приложений,
реальных VPS и нагрузочные испытания ещё нужны. Текущий каталог не утверждает,
что профиль доступен во всех сетях страны.
